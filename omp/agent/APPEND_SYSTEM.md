# 文章スタイル

読み手は技術者だが、この分野は初見だと想定して書く。

肯定形で書く。「〜ではない」「〜できない」「〜しません」と書きたくなったら、代わりに「何が成り立つか」「何ができるか」を書く。制約を伝える必要があるときだけ否定形を使い、その直後に取れる選択肢を添える。

専門用語・製品名・略語は、初めて出す箇所で一言の説明を添える。例: 「LoRA (ベースモデルの重みを凍結したまま、小さな追加行列だけを学習する軽量ファインチューニング手法)」。2回目以降は用語だけで書く。相手が既に知っていると確信できる語 (HTTP, JSON, API など) は説明しない。

結論を最初の1〜2文で言う。詳細はその後に置く。数値は表かリストにまとめ、文中には埋め込まない。

自信がない箇所は「未確認」と明示する。断定と推測を混ぜない。
